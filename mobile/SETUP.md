# صراحة Android — إعداد النشر

## ما اكتشفه فحص المصدر

- الموقع سكربت PHP 8.3 مع MySQL/PDO؛ `inc.php` ينشئ جلسة PHP، ويستخدم تسجيل الدخول `password_verify` وحسابات `users` الحالية. لوحة الرسائل وإرسالها في `dashboard.php` و`u.php`.
- لم يظهر REST API عام موحّد لتطبيق موبايل. توجد نقاط JSON داخلية للذكاء الاصطناعي والإشعارات؛ أُبقيت نقطة تحليل الشخصية الأصلية كما هي.
- المخطط المرفق يضم `users`, `messages`, `message_meta`, `reports`, `sender_bans`, `banned_words`, `settings`, `push_subs` وجداول الإدارة والدعم والمدونة. الرسائل مرتبطة بمالكها عبر `recipient_id`؛ الملف الشخصي يحتفظ بالمؤهلات الموجودة مثل توثيق الحساب واستحقاق تحليل المرسل.
- السكربت يدعم الرسائل النصية والصوتية والصور والاستطلاعات والأسئلة والأجوبة، الملف الشخصي والأمان، OAuth اجتماعيًا، تحليل المرسل، تحليل الشخصية بالذكاء الاصطناعي، ولوحة إدارة. واجهة Flutter الحالية تربط الرسائل النصية والأسئلة والإجابات والإبلاغ والمفضلة والملف وتحليل الشخصية فقط؛ لا تغيّر لوحة الإدارة.
- Push الموجود Web Push في `push_subs` وليس FCM. لا يوجد إعداد Firebase في المرفقات، لذلك لم أضف ترحيلًا أو إشعارات Android وهمية.

## النطاق

التطبيق Flutter أصلي وليس WebView. يستخدم جلسة PHP الحالية وبيانات الموقع نفسها، ولا يتصل مباشرة بقاعدة البيانات أو ينشئ جداول. يحفظ معرّف جلسة PHP في Android Keystore عبر `flutter_secure_storage`.

## الوظائف المربوطة

- تسجيل الدخول بحساب الموقع الحالي.
- صندوق الرسائل والفلاتر والإحصاءات والصفحات التدريجية والتحديث اليدوي.
- المفضلة، حذف الرسائل، الإبلاغ، والإجابة عن الأسئلة.
- إرسال رسالة خاصة أو سؤال نصي دون كشف المرسل.
- الملف الشخصي ورابط المشاركة وتحليل الشخصية بعد موافقة صريحة.
- RTL عربي وحالات التحميل والخطأ والإنترنت غير المتاح.

الرسائل الصوتية تظهر كعنصر مع مدتها، لكن تسجيلها وتشغيلها ورفع الصور والاستطلاعات غير مضمّنة في النسخة الحالية. شاشة الدخول تدعم البريد/اسم المستخدم وكلمة المرور؛ تسجيل الدخول عبر Google/Facebook غير مضمّن، لذا حساب OAuth الذي لا يملك كلمة مرور للموقع لن يسجل من هذه النسخة.

## نشر API على الاستضافة

المتطلبات: PHP 8.3، PDO MySQL، mbstring، قاعدة MySQL/MariaDB الحالية، HTTPS، وApache `mod_rewrite` في مجلد API.

1. خذ نسخة احتياطية من ملفات الموقع وقاعدة البيانات. لا ترفع الحزمة فوق الموقع كله، ولا تستبدل `config.php` أو `inc.php` أو `uploads`.
2. انسخ `deployment/api/v1/index.php` و`.htaccess` إلى `public_html/api/v1/` مع بقاء `inc.php` في جذر الموقع.
3. ملف API نفسه لا يضيف جداول أو أعمدة. تنبيه مهم: `inc.php` الموجود أصلًا ينفّذ ترقية المخطط v12 تلقائيًا عند أول جلسة جديدة (مثل أي صفحة PHP). إذا كانت قاعدة الإنتاج مطابقة للمخطط المرفق، فالفحوصات و`CREATE TABLE IF NOT EXISTS` متوافقة ولا تحذف بيانات؛ أمّا قاعدة أقدم فقد تُضاف إليها جداول/أعمدة ناقصة. خذ نسخة احتياطية قابلة للاستعادة، وافحص نسخة المخطط وصلاحيات مستخدم قاعدة البيانات (`CREATE`/`ALTER`) قبل أول طلب API. لا أستطيع تأكيد حالة قاعدة الإنتاج من المرفقات وحدها.
4. تحقّق أن `https://sarehny.com/api/v1/session` يعيد JSON مع `user: null` دون جلسة، ثم سجّل الدخول من التطبيق بحساب اختبار غير حقيقي.
5. إذا لم يدعم الخادم Apache `mod_rewrite`، اطلب من المستضيف تمكين rewrite داخل `api/v1/` قبل استخدام التطبيق؛ لا يتضمن عميل Flutter مسارًا بديلًا. لا تضف CORS عامًّا؛ عميل Android أصلي لا يحتاج CORS.
6. لا تختبر باستخدام بيانات المستخدمين الموجودة في ملف SQL المرفق. لا تغيّر قاعدة البيانات الحية دون نسخة احتياطية وموافقة.

## المسارات

- `GET session`, `POST auth/login|register|logout`
- `GET inbox?filter=all|questions|pending|published|favorites&page=1&limit=20`
- `POST messages/{id}/favorite|delete|answer|unpublish|report`
- `GET account`, `POST account/profile|username|email|password`
- `GET public-profile?username=...`, `POST public-messages`
- تحليل الشخصية يستعمل نقطة الموقع القائمة `/ai_analyze.php`، ويطلب موافقة قبل إرسال الرسائل المنقّحة لمزوّد الذكاء الاصطناعي. هذا قد يستهلك الحصة القائمة وقد يسبب تكلفة لمزوّد الموقع؛ لا يضيف التطبيق أي شراء.

## البناء

لم تتضمن بيئة v0 الحالية Flutter أو Dart أو Android SDK/Java؛ لم يُنشأ APK أو AAB ولم يمكن تشغيل المحلل أو اختبار جهاز. في بيئة تطوير فيها Flutter 3.32 / Dart 3.8 أو أحدث وAndroid SDK:

1. افتح مجلد `mobile/` وشغّل `flutter create --platforms=android --org com.sarehny --project-name sarehny_mobile .` لإنشاء Gradle Wrapper وملفات بناء Android القياسية مع الحفاظ على `lib/` و`pubspec.yaml` و`AndroidManifest.xml` و`MainActivity.kt`.
2. شغّل `flutter pub get` ثم `flutter analyze` و`flutter test`.
3. للتجربة: `flutter run --dart-define=API_BASE_URL=https://sarehny.com/api/v1/`.
4. للإصدار: `flutter build apk --release --dart-define=API_BASE_URL=https://sarehny.com/api/v1/` أو `flutter build appbundle --release --dart-define=API_BASE_URL=https://sarehny.com/api/v1/` بعد إعداد مفتاح توقيع Google Play الخاص بك.

## إشعارات Android الأصلية

المرفقات تحتوي Web Push عبر `push_subs` فقط. إشعارات FCM تتطلب مشروع Firebase وحزمة Android وإضافة `google-services.json` وبيانات إرسال خاصة بالخادم وجدول رموز أجهزة. لم أضف هذه التغييرات أو أفعّلها دون إعداداتك وموافقتك. لا توجد خدمة مدفوعة مضافة.

## التراجع والقيود

لحذف API من الاستضافة، احذف `public_html/api/v1/` فقط. هذا لا يعكس أي ترقية v12 شغّلها `inc.php` تلقائيًا؛ إذا حدثت ترقية غير متوقعة، لا تحذف جداول يدويًا، واستعد نسخة قاعدة البيانات الاحتياطية بعد تنسيق ذلك مع مدير الموقع. لم تُنفّذ شاشات رفع الصورة أو تغيير البريد/كلمة المرور/اسم المستخدم أو حذف الحساب أو الصوت/الاستطلاعات؛ لا تعرض الواجهة أزرارًا لها. إعداد/تكلفة مزوّد AI يظلان تحت سيطرة إعدادات الموقع.
